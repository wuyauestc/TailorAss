# Contact energy increments

`ContactEnergyDelta` estimates increments of the existing signed IPC energy. It does not replace its E/gradient/raw Hessian, select different contact features, change the material, or alter CCD/Armijo/KKT thresholds. Its native implementation is a separate source file; the original `IPCEnergy.cpp` and upstream files remain unchanged.

`Prepared` owns immutable moving-source rest coordinates, optional fixed visible-body coordinates, physical parameters and finite limits. `capture` retains the actual complete force-producer leaves and actual rounded positions in a snapshot with a private owner identity. `difference` rejects snapshots from another prepared instance. The receipt does not authenticate an arbitrary external producer; the App G objective is the actual force owner and additionally binds each evaluation to its frame.

For an identical canonical feature/dtype/signed-area set, fixed distance increments use point norm increments and quotient increments. For `d²=N/D`, `δd²=(δN-d0²δD)/(D0+δD)`. Small cross changes are formed as `u×δv+δu×v+δu×δv`. The physical barrier remains `-(q-Q)² log(q/Q)`, with `q=d²-dmin²`, `Q=(2dmin+h)h` and scale `kappa*h/Q²`. Its increment uses `log1p(δq/q0)` and the algebraic change of `(q-Q)²`; EE mollifier increments retain the original epsilon and both threshold branches. Source areas retain their signs, including negative improved-max corrections.

The native API supports VV, all EV/FV fixed distance types, and all nine EE types. Automatic distance types must agree at both endpoints. Invalid/nonfinite data, infeasibility, collapsed/near-degenerate geometry, nonnearest rounding and cancellation return explicit failure with a NaN increment; they never return a safe zero. Swift checks cancellation/nearest even for empty groups and bounds snapshots and leaf work. Charged bytes are a conservative payload estimate, not RSS instrumentation.

A changed canonical feature set, changed signed weight, or automatic distance-type transition returns a report with `roundedBlockFallback` and its reason, using the entire original signed block difference. There is no partial stable sum and no missing feature treated as zero. The original array order and Neumaier formula are preserved. G additionally calls `selectingOriginalRoundedFallbacks` with its own preexisting body/self rounded values, so its fallback result and report retain those exact bits. The old rounded metadata remains available while `contactIncrement` records the values actually selected in the total.

These are binary64 estimates, **not universal interval or sign certificates**. In particular a fallback retains the original rounded-energy limitations and reports them. A stable increment is not a new criterion for accepting a force residual or a complete garment.

## Verification

The new nine-test suite covers all primitive types, all nine EE types, positive/negative signed areas, activation and mollifier transitions in both directions, dmin=0 and .5mm, exact identity/rigid coordinate permutation, degenerate/infeasible/nonfinite inputs, early/late cancellation, rounding, budgets, foreign owner, and explicit complete fallback behavior. A complete hot run of the same built product executed **100 tests with zero failures**; this is not an addition of an older 91-test result to the nine new tests.

The real fixture is a new isolated Circle249→250 accepted fifth inner update. It is not the original full-run failed250 candidate or the earlier root fifth update. Its 1,705 signed fixed leaves (including236 negative corrections) were independently recomputed using exact binary64 ratios at80/100 decimal digits. All3,410 original endpoint leaf energies also matched the original native replay bitwise. Twenty-five additional analytic/transition cases have independent high-precision expectations. `Scripts/verify-contact-energy-delta.py` reproduces the high-precision fixture check with developer-only mpmath1.3.0; mpmath is not an App/runtime dependency.

For this sample the original body/self rounded-increment errors were approximately−3.32e−19/−2.13e−19 J, while the stable formula experiment errors were below7e−29 J per group. The ordinary summation error alone was about1e−29 J: the main loss occurred before accumulation. This demonstrates a useful numerical improvement without claiming the sign of every whole objective increment.

The actual arm64 iOS17 and x86_64 iOS17 Simulator smoke builds compile the new C++ primitive, the complete current Swift module, and a real final Swift client linked to the pinned unchanged C++ base. `vtool` and `nm` confirm platform/minimum OS and `_ipced_evaluate_local`. They are compilation/linkage proofs, not device runtime tests. No full garment run was performed for this change.
